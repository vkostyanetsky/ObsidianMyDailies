# Toolbox

[English](README.md) | **Русский**

Плагин для Obsidian, собравший то, что нужно моему собственному хранилищу: переименование вложенных в заметку изображений по имени самой заметки и подсчёт съеденного за день с записью итогов в заметку дня.

> **Персональный инструмент.** Плагин существует, чтобы поддерживать мою собственную работу над разными проектами, и его поведение целиком определяется тем, как я строю заметки для этих проектов. Он не задуман как универсальный плагин для Obsidian, и выкладывать его в каталог сообщества я не планирую. Пользуйтесь им, если ваши заметки устроены так же, но ничего здесь не рассчитано на чужой рабочий процесс.

## Что он делает

Две возможности, четыре команды и два прохода, которые плагин может сделать сам после открытия хранилища:

| Возможность | Команды |
| --- | --- |
| [Переименование изображений](#переименование-изображений-в-текущей-заметке) | **Rename images in current note**, **Rename images in image folders** |
| [Питание](#питание) | **Recalculate nutrition in current daily note**, **Recalculate nutrition in all daily notes** |

## Переименование изображений в текущей заметке

Плагин переименовывает каждое вложенное в заметку изображение по имени самой заметки, нумеруя изображения в порядке их первого появления:

```text
{имя заметки} {номер}.{расширение}
```

Заметке, которая называет своим именем единственное изображение, нумерация не нужна — различать нечего, — поэтому такое изображение получает имя:

```text
{имя заметки}.{расширение}
```

До:

```markdown
![[Test 1.png]]

![[Pasted image 20260808172735.png]]

![[Test 10.png]]
```

После (при одиннадцати изображениях в заметке):

```markdown
![[Test 01.png]]

![[Test 03.png]]

![[Test 05.png]]
```

### Правила

- Нумерация начинается с `1` и дополняется нулями до ширины общего количества: `1`…`9` для девяти изображений и меньше, `01`…`99` — до девяноста девяти, `001`…`999` — дальше.
- Заметка с единственным изображением даёт ему своё имя, без номера — `Test.png`, а не `Test 1.png`. Как только к заметке добавляется второе изображение, оба снова получают номера.
- Расширение изображения сохраняется как есть, вместе с регистром. Распознаются `png`, `jpg`, `jpeg`, `gif`, `webp`, `bmp`, `svg` и `avif`; регистр при сравнении не учитывается.
- Изображения остаются в своей папке; меняется только имя файла.
- Изображение, использованное в заметке несколько раз, переименовывается один раз, получает номер первого появления и не расширяет нумерацию.
- Понимаются обе формы ссылок — `![[Image.png]]` и `![](Image.png)`, в любой папке, — а псевдоним, размер (`![[Image.png|300]]`) и заголовок ссылки остаются нетронутыми.
- Ссылки внутри YAML-фронтматтера, огороженных блоков кода и встроенного кода игнорируются — как и внешние адреса и вложения файлов, которые не являются изображениями.
- Изображение, на которое ссылается и другая заметка, остаётся в покое: оно не принадлежит ни одной заметке в отдельности, и переименование по имени этой заметки лишь отняло бы его у остальных. Номер такому изображению тоже не достаётся, а уведомление сообщает, сколько изображений было пропущено.
- Ссылки, которые не ведут ни к какому файлу, пропускаются: номер им не достаётся, и уведомление сообщает, сколько их было.
- Изображение, у которого уже правильное для его места имя, остаётся в покое — как и ссылка на него.

Переименование планируется целиком до того, как что-либо произойдёт. Если имя, нужное плану, уже занято файлом за пределами заметки, не переименовывается ничего, а уведомление называет этот файл. Каждое изображение переименовывается прямо в своё новое имя, как только оно освобождается. Изображения, забирающие имена друг у друга — заметка, где `Test 10.png` должно стать `Test 05.png`, а другое изображение — как раз `Test 10.png`, — ждали бы друг друга бесконечно, поэтому одно из них переносится во временное имя, кольцо размыкается, и остальное идёт следом. Ни один файл никогда не перезаписывается, а изображение, чьё имя свободно, переименовывается один раз, а не дважды. Если переименование срывается на середине, уже сделанное берётся обратно.

Переименование идёт через файловый менеджер Obsidian, поэтому уважает настройку **Automatically update internal links**: когда она включена, ссылки переписывает сам Obsidian, а плагин лишь проверяет результат; когда выключена — плагин переписывает ссылки текущей заметки одним отменяемым шагом. Ссылки на изображения из *других* заметок в любом случае остаются заботой Obsidian.

## Переименование изображений в папках изображений

То же самое переименование, применённое к каждой заметке **папок изображений**, указанных в настройках, — одна заметка за другой. Открытые заметки правятся через редактор, поэтому изменение остаётся отменяемым; остальные записываются прямо на диск.

Одно уведомление подводит итог — сколько изображений переименовано в скольких заметках — и называет каждую заметку, которую пришлось оставить в покое, с причиной.

## Переименование при открытии хранилища

Со включённой настройкой **Rename images when the vault is opened** описанный выше проход случается один раз сам: сразу после того, как Obsidian прочитал хранилище, заметки папок изображений просматриваются и всё, что лежит не на своём месте, приводится в порядок. Сообщает о себе только тогда, когда что-то переименовал или сорвался.

Это один из двух проходов, о которых никто не просил, — второй описан ниже, в разделе про питание. За хранилищем плагин не следит: заметку он не трогает, пока её пишут, и изображения не двигаются под руками. Всё остальное происходит по запуску команды.

Поскольку изображение, показанное в нескольких заметках, не переименовывается никогда, две заметки с общим изображением не могут перетягивать его друг у друга.

## Питание

Плагин складывает то, что записано в записях о еде за день, и пишет итоги — калории, белки, жиры, углеводы и воду — в свойства заметки того дня.

Числа получаются те же, что показывает `Питание.base` в представлении **День**, и считаются они так же, как считает база.

### Что читается

Участвуют три вида заметок:

- **Записи** — все заметки **папки записей о питании**, вместе с вложенными. Запись указывает день в `date`, ссылается на продукт в `product` и указывает съеденное количество в `quantity`.
- **Продукты** — та заметка, на которую ссылается `product` записи, где бы она ни лежала. Продукт указывает `calories`, `protein`, `fat`, `carbs` и `water` на один свой `unit_size`.
- **Заметки дня** — заметки **папки заметок дня**, названные по дню: `2026-08-28` и тому подобное. Всё остальное в этой папке — вложение, рисунок, названный по дню, когда он был сделан, — остаётся нетронутым.

Запись и продукт, на который она ссылается:

```yaml
date: 2026-08-27                 calories: 120.3
product: "[[Пирог с рыбой]]"     protein: 10
quantity: 148                    fat: 4.5
                                 carbs: 10.2
                                 water: 0
                                 unit_size: 100
```

### Как считается

Каждая запись считается отдельно и округляется, и уже округлённые величины складываются:

```text
round(product.calories / product.unit_size * quantity)
```

Ровно это делает база: её колонки округляют каждую строку, а итог складывает округлённые строки. Округление суммы вместо этого уводило бы на единицу-другую от чисел на экране.

Запись, продукт которой не ведёт ни к одной заметке, пропускается и попадает в сообщение; то же и с записью без количества, и с нутриентом, которого продукт не указывает. День, в который ничего не съедено, выходит нулями.

### Что записывается

Итоги попадают в свойства заметки дня, под теми именами, что заданы в настройках:

```yaml
---
weight:
steps:
gym:
timestamp: 1755706724
calories: 1387
protein: 72
fat: 57
carbs: 143
water: 1600
---
```

Трогаются только эти строки. Свойство, которое уже есть, остаётся на своём месте, отсутствующее дописывается в конец блока, а всё прочее — порядок, отступы, кавычки, свойства, о которых плагин ничего не знает, — остаётся байт в байт как было.

**Заметка записывается только тогда, когда хотя бы одно число вышло другим, чем в ней уже написано.** Проход по хранилищу из тысячи дней, в котором ничего не изменилось, не пишет ничего и не трогает тысячу дат изменения.

### Recalculate nutrition in current daily note

Считает день открытой заметки и записывает его. Сообщение показывает итоги, число записей, из которых они сложились, и все ссылки на продукты, которым не ответила ни одна заметка.

Команда вообще не предлагается, если открытая заметка не соответствует дню — сегодняшнему или любому другому. На чём угодно ещё она не появляется в палитре команд, а назначенное на неё сочетание клавиш ничего не делает.

### Recalculate nutrition in all daily notes

То же самое для каждой заметки дня в хранилище. Записи читаются один раз и группируются по дням, так что проход не перебирает их заново ради каждой заметки. Одно сообщение подводит итог: сколько заметок записано и из скольких.

### Подсчёт питания при открытии хранилища

Со включённой настройкой **Recalculate nutrition when the vault is opened** описанный выше проход случается один раз сам, сразу после того, как Obsidian прочитал хранилище. Сообщает о себе, только если что-то записал или сорвался. Дальше ничего не отслеживается: записи можно добавлять и править весь день, и ни одна заметка дня не сдвинется под руками.

## Отладочный вывод

Всё, что плагин делает с хранилищем, пишется в консоль разработчика (`Ctrl+Shift+I` → **Console**, фильтр по `[Toolbox]`): сколько заметок хранилища рассмотрел проход; каждое переименование изображения; каждое изображение, оставленное в покое из-за того, что его используют другие заметки — с перечислением по одному; каждая записанная обратно заметка и число переписанных в ней ссылок; сколько записей о питании прочитано и откуда; каждая заметка дня, в которую записаны итоги. Заметки, которые обработать не удалось, выводятся предупреждениями.

## Настройки

| Настройка | Что делает |
| --- | --- |
| **Image folders** | Папки, с которыми работают обе описанные выше возможности, вместе с вложенными. Их может быть сколько угодно; каждая строка выбирает папку хранилища, пустые строки игнорируются. Корень хранилища папкой указать нельзя — папку нужно назвать. |
| **Rename images when the vault is opened** | Просматриваются ли эти папки один раз при запуске. Включение ничего не меняет сразу же — оно вступает в силу при следующем открытии хранилища. Чтобы пройти по папкам сейчас, запустите команду. |
| **Nutrition records folder** | Папка, в которой лежат записи о еде, вместе с вложенными. Если её не задать, ничего не считается, и обе команды питания так и сообщают. |
| **Daily notes folder** | Папка, в которой лежат заметки дня. Если её не задать, берётся папка встроенного плагина **Daily notes**. |
| **Calories**, **Protein**, **Fat**, **Carbohydrates**, **Water** | Свойства заметки дня, в которые записывается каждый итог. Оставленное пустым свойство возвращается к своему значению по умолчанию (`calories`, `protein`, `fat`, `carbs`, `water`). |
| **Recalculate nutrition when the vault is opened** | Считается ли каждая заметка дня один раз при запуске. Как и выше, включение вступает в силу при следующем открытии хранилища. |

Папки сопоставляются без учёта регистра, и папка содержит всё, что лежит ниже, так что `Projects` покрывает и `Projects/2026/Trip.md`.

## Как пользоваться

Откройте заметку и запустите **Rename images in current note** из палитры команд (`Ctrl/Cmd+P`). Чтобы вместо этого пройти по папкам изображений, запустите **Rename images in image folders**.

Откройте заметку дня и запустите **Recalculate nutrition in current daily note**, чтобы записать её итоги, или **Recalculate nutrition in all daily notes**, чтобы пройти по всему хранилищу.

Все четыре работают только по запуску. Ничего не переименовывается, пока заметку правят, и ни одна заметка дня не записывается, если ни одно число в ней не изменилось.

## Сборка

Требуется Node.js 18 или новее.

```bash
npm install
```

Производственная сборка — проверяет типы и пишет `main.js`:

```bash
npm run build
```

Сборка для разработки, с пересборкой при изменениях:

```bash
npm run dev
```

Модульные тесты:

```bash
npm test
```

## Развёртывание в хранилище

Путь к хранилищу лежит в вашем собственном файле `.env`, которого в репозитории нет. Скопируйте пример и впишите в него свой путь:

```bash
cp .env.example .env
```

```ini
OBSIDIAN_VAULT=D:\Me\Vault
```

Затем соберите плагин и скопируйте его в это хранилище одной командой:

```bash
npm run deploy
```

Она пишет `main.js`, `manifest.json` и `styles.css` в `<vault>/.obsidian/plugins/toolbox/`, создавая папку, если её там нет. Для одного запуска можно указать другое хранилище — первым аргументом (`node scripts/deploy.mjs "C:\Path\To\Vault"`) или переменной окружения `OBSIDIAN_VAULT`; и то и другое важнее `.env`. Папка, внутри которой нет `.obsidian`, отвергается; ничего не копируется, пока `main.js` не собран; а об отсутствующем `.env` сообщается, а не додумывается.

В VS Code то же самое запускается из палитры команд (`Ctrl+Shift+P`) → **Tasks: Run Task**:

- **Deploy plugin to Obsidian vault** — собирает, затем копирует;
- **Copy plugin to Obsidian vault (no build)** — копирует тот `main.js`, который лежит там прямо сейчас; удобно рядом с `npm run dev`.

Обе описаны в [.vscode/tasks.json](.vscode/tasks.json) и могут получить собственное сочетание клавиш через **Preferences: Open Keyboard Shortcuts (JSON)**:

```json
{
	"key": "ctrl+alt+d",
	"command": "workbench.action.tasks.runTask",
	"args": "Deploy plugin to Obsidian vault"
}
```

После первого развёртывания перезапустите Obsidian (или перезагрузите приложение) и включите **Toolbox** в **Settings → Community plugins**; после следующих достаточно перезагрузить плагин.

Можно и иначе: чтобы разрабатывать в живом хранилище, ничего не копируя, клонируйте этот репозиторий прямо в `<ваше хранилище>/.obsidian/plugins/toolbox/`, запустите `npm run dev` и перезагружайте плагин после каждого изменения.
